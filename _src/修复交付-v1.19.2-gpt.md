## 产品口径确认

用户在本次对话确认采用方案 6.4：**邀约卡不受学院额度限制；完成预咨询后，学院额度限制人工预约入口。** 因此 R9 的限制放在 `ivAllocate()`，没有放在 `ivSendGo()`。

## 文案修改

文案沿用现有组件，分别提交 COPY-STU、COPY-ADM、COPY-SCHED、COPY-INV。修改的是学生和老师实际会看到的文字，包括邀约、预咨询、预约状态、求助、工作台、危机记录、设置、排班和额度提示。

- 用“谁做什么、什么时候生效”说明下一步，例如“老师提出了新时间，请确认是否合适”。
- 删除“卡住了需要你推一下”“必须你拍板”等含混说法。
- “聊完就可以选时间”改为说明有空余时段时选择、没有时等待通知。
- “本窗口尚可承接”改为“未来 30 天可安排”；“放 2 个成可发”改为“释放 2 个额度”。
- 风险词原文、问卷算法和学生与小屿对话的识别规则不因文案清理而改变。

## 已走通的主要流程及函数链

- **A 普通预约**：`pickSlot → bookSubmit → stu_snapshot → fromStu → LY_in(book) → confirm → ikOpen/ikFinish → bOk → bookChanged → fromAdm → 学生已确认`。跳过、完成发送、改期、取消与待确认时间线有回归。
- **B 主动邀约**：`ivSendGo/zIvc → ivPublic/ivReceive → ivAcc → ivGoIk → ikFinish → ivTouch → ivcReply → ivAllocate → ivEntry → pickSlot → bookSubmit`。另覆盖保存/关闭恢复、不参加二次确认、排队、“轮到你了”、最多三个方便时间及重新开放。
- **C 咨询师处理**：`enter(L2) → booking/man → bOpen/ACT.mo(intake) → bOk / bMoveOk / bNoOk → bookChanged → fromAdm → stu_bridge`。查看审计、新时间接受、婉拒留言和重新选时均有回归。
- **D 中心配置**：`ivAddGo/ivFileIds → 持久核对 → ivSendGo → aiRows/ACT.mo(ivIk) → ikBank/iktSave/iktRestore → 排班动作/schedRegGo → poolR/poolH/poolAppOk → ivAllocate`。两套题库独立、切换未保存保护、学院额度、通知和审核均已验证；撤回同意的数据来源仍为上表待确认项。
- **E 管理员**：`setTab(duty) → dutyReadOnly`；只读值班表与权限设置可达，不能通过摘要/预约动作越权。
- **F 风险词**：`谈话保存/追加 → TALK_RE → 新增词比较 → newCrisis覆盖链 → 新建或追加现有危机`。604 个词、99/195/310 分组、否定词、三级不报告、二级一般时限、一级紧急与草稿提醒有回归。
- **G 两端联动**：`LY_snap/stu_snapshot → fromAdm/fromStu → sendIvcPending → 两端接收 → ack`。两套题库下发、邀约来源及摘要、老师确认回传、追加后婉拒再提交和重复渲染已验证。
- **H 本机保存**：`KEEP保存 → reload → KEEP恢复 → 实例/修订号比较 → 两端恢复`。双题库独立、批次/号池保留、预约数量和 ID 不变，未重复生成演示预约。

这些是单页双端演示的代码和浏览器回归结果。未提供的撤回同意数据通道没有编造为已走通。
